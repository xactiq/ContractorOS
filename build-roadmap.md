# ContractorOS Build Roadmap

## Phase 1 — Foundation MVP
Goal: make it real and demoable fast.

Build:
- Leads_CRM
- Jobs_Master
- Measurements
- Price_Lists
- Line_Item_Library
- Line_Item_Pricing
- Estimate_Header
- Estimate_Lines
- basic print outputs
- Branding_Settings

Definition of done:
- one demo job can go from lead to estimate
- one branded estimate prints cleanly
- pricing is table-driven

## Phase 2 — Supplement MVP
Goal: create the killer feature.

Build:
- Carrier_Estimate_Header
- Carrier_Estimate_Lines
- Item_Match_Map
- Supplement_Findings
- Supplement_Output
- supplement worksheet print view
- supplement letter print view

Definition of done:
- import carrier estimate by manual or spreadsheet path
- compare to internal estimate
- produce draft supplement package

## Phase 3 — Job Ops Pack
Goal: make it usable after the sale.

Build:
- Tasks_Followups
- Invoices_Payments
- Documents_Register
- production docs
- completion certificate
- invoice and waiver outputs

Definition of done:
- sold job can be tracked through completion and payment

## Phase 4 — Profit Layer
Goal: make the owner care about it every week.

Build:
- Profitability
- dashboard KPIs
- close rate metrics
- supplement uplift tracking
- source-to-profit reporting

Definition of done:
- owner can see pipeline, cash, and gross profit snapshot

## Phase 5 — Import Enhancements
Goal: reduce admin drag.

Build:
- measurement import workflow for ESX/aerial files
- better carrier PDF/XLSX parsing
- rule library for common missing-scope patterns
- alias mapping admin tools

Definition of done:
- system handles common import scenarios without excessive cleanup

## Phase 6 — Sellable Package
Goal: make it easy to sell repeatedly.

Build:
- sandbox demo brand
- onboarding checklist
- setup worksheet
- user guide
- pricing sheet
- sample outputs for marketing

Definition of done:
- someone can buy, brand, and launch the system with a repeatable process

## Recommended immediate next build tasks
1. Create actual table shells / CSVs
2. Build a demo brand profile
3. Define estimate print mapping
4. Define supplement worksheet mapping
5. Choose MVP input path for carrier estimate import

## Important restraint
Do not try to make v1 do everything.
The right play is:
- credible core engine
- fast supplement story
- clean outputs
- repeatable white-labeling
